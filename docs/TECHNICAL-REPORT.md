# 来源审计（Provenance Guard）
## 面向检索增强生成的证据谱系审计插件 · 技术报告

**版本** v0.8.0　|　**日期** 2026-11-11　|　**形态** DSH 宿主侧插件（Host-only，含可选客户端面板）

---

## 摘要

检索增强生成（RAG）把"模型能查到多少条结果"变成了"模型能引用多少条证据"。但检索结果的数量并不等于证据的独立性：一条被四十个内容农场复述的说法，在检索层表现为四十条"互不相同的来源"。本文提出并实现 **来源审计（Provenance Guard）**——一个在检索结果进入模型上下文之前运行的确定性审计层。它把 N 条结果折叠为 K 条相互独立的来源谱系，判定其中是否存在生成性来源（机构/论文/公报），并将证据强度量化为 A/B/C/D 四级**可执行句式**；当且仅当结果集呈现可机械判定的失真形态时，才向模型输出一段审计结论，并以有界预算完成一次原文补证。系统不含模型调用、不修改检索结果、不对事实真伪做出判断。在 22 个真实场景的对照测试中，系统与人工判断一致 21 例；在连续两日的真机运行中累计审计 19 次检索，其中 3 例判为 A、13 例判为 C、3 例判为 D。

**关键词**：检索增强生成；来源谱系；证据强度；信息溯源；内容农场；可解释性

## 1 引言

### 1.1 一个正在扩散的失效模式

大语言模型在联网检索后撰写内容时，默认把"检索到的条目数"当作"证据的份数"。这一假设在两类内容上系统性失效：

1. **通稿与洗稿**。同一篇稿件被门户、聚合站与自媒体改标题后重复发布，检索层看到的是十余个域名，语义层只有一条信息。
2. **内容农场**。批量生成的同模板文章围绕同一断言展开，措辞不同、结论一致，进一步稀释了"独立性"这一概念的统计意义。

其后果不是"回答错误"，而是更隐蔽的一种：**回答语气与证据强度不匹配**。模型以"数据显示"的确定性复述一个只在自媒体间循环的数字，读者无从察觉。

### 1.2 本文的立场

我们不试图判断内容真假——这既超出确定性系统的能力，也会把错误从"过度自信"转移为"过度否定"。本文只做一件可机械检验的事：**度量证据的形状**。

> 它不能告诉你什么是真的，但它能阻止你把"一个来源被复制了五十遍"当成"五十个来源都在说"。

### 1.3 主要贡献

1. **形式化**：把检索结果集折叠为独立谱系数 K，并给出三个可确定性判定的失真信号（谱系坍缩、一手源缺失、归因断裂）。
2. **判级**：将证据强度映射为四种可执行句式（A 可断言 / B 单源可断言 / C 仅可转述 / D 不可坐实），而非一个无法落地的评分。
3. **静默优先的输出策略**：以规则树决定"是否出声、出声多长"，避免高频提示被模型习得性忽略。
4. **有界补证**：以每次至多一次页面抓取（及一次指纹检索）的预算，把"无一手源"推进为"原文有/无该数字"。
5. **可核查台账**：将每次审计的 N/K/等级/出处/转述数持久化，使"我查过什么"成为可回溯的工程记录。

## 2 问题定义

### 2.1 形式化

设一次检索返回结果集 \(R = \{r_1, \dots, r_N\}\)，每条结果携带站点 \(s_i\)、标题 \(t_i\)、摘要 \(p_i\)、发布时间 \(\tau_i\)。定义独立谱系数

\[
K = \bigl|\{\,C_1, \dots, C_m\,\}\bigr|,\quad C_j \subseteq R
\]

其中谱系由等价关系生成：同站点、标题 3-gram 相似度 ≥ 0.8、摘要 4-gram 相似度 ≥ 0.6、或共享任一精确细节指纹（精确数字、引号短语）。纯自媒体构成的谱系不计入 K——十篇公众号不是十个来源。

### 2.2 三个可机械判定的信号

| 信号 | 判定 | 含义 |
|---|---|---|
| **S1 谱系坍缩** | \(K \ll N\) 且最大谱系占比高 | 多条结果实为一份内容 |
| **S2 一手源缺失** | 结果集中无生成性来源（机构/论文/公报/协会） | 只有转述，没有原始文件 |
| **S3 归因断裂** | 文本含"据报道/有消息称"且未指向具名机构 | 无法追溯谁在说 |

### 2.3 非目标

- 不判断命题真伪，不输出"真/假"标签；
- 不删除、不重排、不改写检索结果；
- 不替代人工核查，不产生新的信息源。

## 3 系统设计

### 3.1 总体架构

系统以 DSH 插件形式运行于宿主进程，挂载在工具执行后的 `tools/post-execute` 阶段：

```
工具调用（web_search）
   │
   ├─ 结果进入上下文前 → 审计层（确定性、零网络）
   │      折叠 → 判级 → 出声决策 → 渲染审计条
   │
   └─ 若值得补证 → 后台有界抓取（L1/L2）→ 下一轮以注入消息回填
```

不引入模型调用，不写会话日志以外的状态；插件内存中的台账另行落盘（见 3.8）。

### 3.2 谱系折叠

采用并查集（union-find）单遍构造等价类，四类边的优先级为：同站点 > 标题近似 > 摘要近似 > 细节指纹。细节指纹取精确数字（含小数的百分比、四位以上整数）与引号短语，是抵抗"改写式洗稿"的最后一道边。

折叠结果同时输出：谱系数 K、站点数、平台类占比、最大谱系规模及其站点分布。

### 3.3 权威分层

每条结果归入三级之一：

| 层级 | 判据 | 例 |
|---|---|---|
| **primary（生成方）** | 政府/教育/国际组织后缀；论文与预印本站点；机构白名单（如 `cpcaauto.com`、`cninfo.com.cn`）；`org`/`org.cn` 且域名含机构词根 | 统计局公报、协会月报、论文原文 |
| **platform（自媒体/聚合）** | 公众号、头条号、百家号、知乎、微博等 | 营销号、个人号 |
| **media（媒体）** | 其余 | 门户、大报、通讯社 |

媒体层内另设**大媒体名单**（通讯社、央媒、财经大报等），仅用于说明"这是媒体转述而非内容农场"，**不参与升级**。

### 3.4 证据强度判级

判级回答的不是"可信度几分"，而是"这句话最多能写成什么样"：

| 等级 | 条件 | 允许的句式 |
|---|---|---|
| **A** | 有生成方 且 K ≥ 2 | 「数据显示……」（注明来源，可给交叉印证） |
| **B** | 有生成方，但仅一条谱系 | 「据……数据」（注明生成性来源） |
| **C** | 无生成方，但可具名上游或存在独立谱系 | 「据 X 报道……」（不可去来源化） |
| **D** | 数字自相矛盾 / 无任何独立谱系 / 单谱系被 ≥4 站点复述 | 「有说法称……（未获独立证实）」（不给具体数值） |

### 3.5 出声策略：静默优先

输出长度由规则树决定，而非加权总分：

| 情形 | 档位 |
|---|---|
| 有生成方且无数字漂移 | **静默**（不输出任何内容） |
| 生成方在集内但其摘要未含该数字 | 简条（附"权威页未及该数字"提醒） |
| 数字漂移 | 全条 |
| 全部来自自媒体/聚合 | 简条 |
| 仅 1 条谱系且 N ≥ 4 | 全条 |
| K ≤ 2 且 N ≥ 6 | 全条 |
| 其余 | 静默 |

**设计依据**：若每次检索都提示，模型将习得性忽略提示；静默是常态，出声才携带信息量。

### 3.6 异步补证

当结果集值得警告且无生成方时，后台发起至多一次原文抓取（L1）：取最早的可追溯媒体页面，检查其是否含该数字、是否给出机构与方法说明。若 L1 无结论，再以引号包裹的指纹数字发起一次检索（L2）。补证结论以注入消息并入下一轮，**不阻塞本次工具返回**。

### 3.7 单点核查

提供显式工具 `audit_claim(claim)`：对一条具体断言执行"一次指纹检索 + 一次页面抓取"，并**以原文而非结果集组成**判级：

| 观察 | 结论 |
|---|---|
| 未取得原文 | 封顶 C |
| 原文含该数字且有机构/口径 | B（原文即生成方）或 C（原文为媒体） |
| 原文含该数字但无机构/口径 | C |
| 原文不含该数字 | D（可能为转述时添加） |
| 检索结果 < 3 条 | 证据不足（不判级） |

### 3.8 台账

每次检索记录 `时间 / N / K / 等级 / 档位 / 站点数 / 平台数 / 主张数字 / 最早出处 / 转述数 / 一手源`，按会话持久化（原子写入，上限 8 会话 × 20 条），并通过同源只读路由提供给客户端面板。作用有二：模型可查询"我已看过什么"，避免重复检索；研究者可回溯"这条结论当时基于什么"。

## 4 用途

| 场景 | 具体用法 |
|---|---|
| **写作前核查** | 把要写进稿子的数字丢进去核查，得到"能不能写成肯定句"的结论与可点开的原文 |
| **识破通稿** | 一条新闻被十家转载时，折叠出真实谱系数，避免把转载量当证据量 |
| **辨别"多方报道"** | 判断"多家媒体报道"是多家独立采访，还是同一篇通稿的多个域名 |
| **尽调与选品** | 面对行业数据（渗透率、均价、规模）时，区分机构原始口径与二手复述 |
| **内容平台选题** | 快速识别某个"爆款数据"是否只存在于自媒体闭环中 |
| **团队留痕** | 台账记录每次判断的依据，供复核与复盘 |

## 5 评估

### 5.1 场景矩阵

构造 22 个真实场景（不同统计口径、不同年份、不同地区、通稿、内容农场、官方自媒体等），每例先写出"谨慎的人类会如何判断"，再与系统输出对比：

- **一致 21/22**；
- 唯一不符：政府机关的微信公众号发布（S16）——域名层面与个人公众号不可区分，系统如实降级为 D 并在提示中注明"域名无法区分机构官方账号"。

### 5.2 真机台账

连续两日真实使用，累计 19 次检索：**A = 3、C = 13、D = 3**。

C 占多数并非"来源质量差"，而是判级规则的必然结果：A/B 要求结果集中出现生成方，而中文检索的前若干条中生成方很少出现。C 的语义是"没有机构原文，只能转述"，而非"来源不可信"。

### 5.3 成本

| 项 | 实测 |
|---|---|
| 审计条（全条） | 约 8–10 行，≤ 900 字符 |
| 异步补证 | 后台一次抓取，实测单次约 11.2 秒，不阻塞返回 |
| 单点核查 | 一次检索 + 一次抓取，上限 12 秒/次 |

## 6 局限

1. **只判形状，不判真假**：一条真实但唯一的独家消息同样会被判为 D。
2. **默认只看元数据**：标题、摘要、时间、域名；正文仅在有界补证与单点核查中读取一篇。
3. **中文场景为主**：停用词、机构名录、媒体名单以中文语料构建。
4. **官方自媒体无解**：政府/机构的公众号与营销号在域名上不可区分（S16）。
5. **抓取受制于外部条件**：目标站点反爬或超时会使补证退化为"未核实"。
6. **非百分比数字**不做漂移检测。

## 7 相关工作

- **检索增强生成**：Lewis 等将外部检索引入生成流程，显著降低事实性错误，但未处理检索结果内部的冗余与同源问题。
- **知识投毒**：PoisonedRAG 等工作表明，向知识库注入少量文本即可劫持回答，攻击成本远低于防御成本。
- **幻觉检测**：以语义熵度量模型输出的不确定性，与本工作在"不确定性"上互补——前者度量模型，后者度量证据。
- **内容来源标准**：C2PA 等内容凭证倡议从生产端为媒体签名，本工作从消费端（检索结果）反推谱系，二者可组合。

## 8 结论

检索增强生成的瓶颈正在从"能不能查到"转向"查到的东西算不算证据"。本文的贡献不在于给出更聪明的判断，而在于把一个模糊的问题（"这数据靠谱吗"）降解为一组可机械计算、可被反驳的量：谱系数 K、生成方是否存在、数字是否出现在原文、转述链的起点在哪。

系统的输出不是答案，而是**句式的边界**：A 可以断言，C 只能转述，D 不能给数字。这一转译使"证据强度"第一次成为模型可以直接执行、读者可以直接复核的指令。

## 附录 A 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `minSources` | 3 | 少于该数不判定 |
| `maxBlockChars` | 900 | 审计条长度上限 |
| `extraPrimaryHosts` | `[]` | 追加的生成方域名 |
| `verify` | `false` | 是否启用补证 |
| `asyncVerify` | `false` | 补证是否后台执行 |
| `maxProbes` | 2 | 单会话补证上限 |
| `verifyTimeoutMs` | 12000 | 单次网络上限 |

配置文件：`$DSH_HOME/provenance-guard.json`（优先级高于插件 patch，改动即生效）。

## 附录 B 术语

- **谱系（lineage）**：内容上同源的一组结果。
- **生成方（primary source）**：产生原始数据的机构、文件或论文。
- **坍缩（collapse）**：多个结果被折叠为少量谱系的程度。
- **锚定（anchored）**：断言中的数字确实出现在被引用页面中。

## 附录 C 文案提炼（口播用）

**一句话**：它不告诉你什么是真的，它告诉你这句话你能写多硬。

**三句话**：
1. 八条新闻，可能只是同一篇稿子抄了八遍——它先数一遍。
2. 想知道一个数字靠不靠谱，它去抓原文：那一页到底有没有这个数。
3. 写稿时它只允许你写"据 X 报道"，而不是"数据显示"。

**三个可选标题**：
- 《AI 引用数据前，我先让它数一遍来源》
- 《8 条新闻其实是一条：我做了个插件专治数据投毒》
- 《它不判断真假，只告诉你这句话能写多硬》

**必须说的一句免责**：它判断的是证据的形状，不是事实的真伪。
